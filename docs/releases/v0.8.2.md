# Nila 0.8.2 — Ask Your Connected Apps

- Ask normal local Web/CLI chat to read connected Google services: YouTube channel/playlists, Gmail inbox, Drive metadata, Classroom courses and Meet conference history.
- Paste a Google Doc or Sheet link to summarize it; Sheets supports ranges such as `A1:C10`. Missing IDs and permissions produce guidance instead of invented data.
- YouTube video links retrieve metadata and descriptions, not the video's audio or transcript. Google tools remain read-only: no email sending, document editing, meeting creation or joining calls.
- English, common Manglish and Malayalam service/read phrases are recognized. Explicit negative requests block account reads. Supported short follow-ups can reuse the last Google source in the same chat.
- Private Google requests do not use public web search, Learning Lab/Gemini or automatic memory extraction. Tool calls come only from the user's request, never instructions found inside retrieved documents. Telegram does not gain access to Google accounts through its memory-sharing toggle.
- Unify Pages deployment under `.github/workflows/static.yml`: build the landing page before upload, deploy only `web/public/about`, and remove the competing `pages.yml` workflow.

Connect each service once in Workspace → Google or `nila google connect SERVICE`. The separately delivered PHP OAuth ZIP remains compatible and is not included in this repository. Live Google accounts still require your own configured OAuth server and consent.
