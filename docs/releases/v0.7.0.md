# Nila 0.7.0 — Shared Models

- **Fast**: `qwen3:0.6b` for quick, lightweight tasks.
- **Medium**: `qwen3:1.7b` for balanced everyday help.
- **Smart / Current**: `qwen3:4b`, the new-install default for more demanding tasks.

A central model service powers Web, CLI and Telegram. Switch without restarting. Existing custom selections remain; missing models are reported with an install command. Model names can be remapped in the Models dashboard. Model size does not guarantee speed or correctness on every device.

CLI: `nila model`, `nila model use fast|medium|current`, or an installed model name. Telegram: `/model`, `/model fast|medium|current`.

The composer uses icons for search, thinking, microphone, speech-stop and models, with accessible labels and tooltips. The supplied Nila lotus logo appears in the sidebar, message avatars and favicon.

Each request picks one thinking phrase and animates dots until response text begins. Telegram edits one temporary message into the answer, with throttled partial updates. Failed or cancelled requests stop the animation.

Public web questions no longer inherit the user's profile or an old Nila developer answer. Identity shortcuts match direct questions about Nila only. Founder/creator lookups trigger web retrieval when search is enabled. Search Off still performs no retrieval; provider availability remains dependent on network access.

Memory now reports personal facts, pending suggestions, accepted Learning Lab lessons, saved web topics, recall switches and recent Learning Lab errors. Opening it recovers source references from older completed answers once, without recreating intentionally forgotten items afterward. Web evidence and accepted lessons stay encrypted and can be used offline. Uncertain/failed Learning Lab reviews are not silently treated as learned facts.

Gemini still receives only consented Learning Lab exchanges, never ordinary chats, profile, files or personal memory. These improvements use saved reference retrieval, not model-weight training.

Validation covers mocked Ollama routing for all three profiles, persistence, missing-model errors, external founder isolation, old evidence recovery, Telegram indicator lifecycle, and browser streaming/controls. Actual model throughput, microphone hardware and a live Telegram account require testing on the user's device.
